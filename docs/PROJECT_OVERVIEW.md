Product Name: Huxley

Description: This is a long term project. The goal of this project is to build a platform that at it's core is an automation/workflow engine (similar to n8n and rewst). The automation engine should have the common tools and options, such as reusable scripts and templates and should support organizational variables. It should have a node based canvas for building and visualizing workflows. It should allow workflows to be created through MCP (bring your own key), the workflow canvas (with Jinja support for data manipulation), and complete workflow design with code. Integrations to other systems are added by importing OpenAPI specs and the integration/actions/auth are built from that. It should support an organizational structure, allowing for sub-organizations and allowing integrations and organizational variables and workflows to be be able to be inherited. The auth system should support local users but also OIDC connections such as with Entra. The engine should support callbacks and creating webhooks. It should support designing forms that people fill out to run automations. It should allow building custom data sets from integrations to be able to query this information. Security and reliability are a must in the design. The backend core functionality should be written in Rust, while anything frontend should be written in Svelte/SvelteKit. The workflow canvas should use SvelteFlow. It should be deployable through Docker and support services like DigitalOcean and Azure for deployment. It should also allow for scaling so it stays resilient and fast depending on the size of organization and the workload. The platform should be licensed with the MIT license. On top of the base automation engine the platform should also have other modules that MSPs, MSSPs, and service desks need to operate. It should include the common features of a PSA platform (like ConnectWise PSA and HaloPSA) for ticketing (modern ITIL aligned and use service queues instead of boards).. asset/configuration/knowledge management and dependency mapping.. contracts and warranties, stock and inventory, change management.. ticket import/processing from M365 and IMAP mailboxes, AI powered abilities like ticket sentiment analysis, ticket triaging, ticket dispatching, and ticket insights from the analysis of the ticket as well as automatic documentation.. customer service features like CSAT surveying and NPS and identifying clients that may not be happy overall based on sentiment and CSAT/NPS. It should provide sales and procurement functionality as well (like ConnectWise PSA and ConnectWise CPQ) including a sales pipeline with opportunities/leaders, quoting, activity tracking and client communications, forecasting, purchase orders/sales orders. It should be able to provide analytics and reporting features such as custom widget/report/dashboard builders that allow people to build their own as well as submit to be published to others in the organization. It should at some point include an invoicing/billing system as well, so include that in the plan. There should be a comprehensive RBAC and permission system that is very granular. The system should provide a client portal option as well that the RBAC and permission system covers that can show data like a clients tickets, assets, widgets, etc. These different tools on top of the core automation system should create system workflows in the engine for things that are automated like probing a mailbox for new tickets. The tool should allow technicians to view clients to be able to see their information or perform actions on the client, these actions are system made forms in the automation engine that run a workflow when run... for example creating a new M365 User, just as an example. The platform should include an AI assistant as well as the MCP mentioned earlier. The system should use PostgreSQL for data storage as well as redis/valkey if needed. As I said the project is to build this platform, that is free and opensource and easily deployed, for MSP's/MSSP's/service desks so they don't have to be locked in to expensive SaaS products and the product is easily extensible through building automations and integrating other platforms to perform actions or get information from to store in the platform. The automation canvas... the platform.. the ticketing.. everything should have a modern intuitive design that makes getting the information or performing the action needed super easy.
